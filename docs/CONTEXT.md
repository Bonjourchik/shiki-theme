## Gotchas

- Проверка в залогиненном виде: тема подкладывается в открытую вкладку shikimori.io, где вошёл пользователь, —
  файлы темы хранятся в `localStorage` этой вкладки (`bjTheme` — файлы, `bjApply` — применить),
  на каждой новой странице: `eval(localStorage.getItem('bjApply'))`. Снимать HTML страниц аккаунта
  и переносить его на стенд нельзя — система безопасности блокирует это как вывод данных. После работы
  очистить: `localStorage.removeItem('bjTheme'); localStorage.removeItem('bjApply')`.

- Пользователь смотрит предпросмотр в панели шириной ~783px (планшетная раскладка сайта 768–1023) — проверять и на этой ширине, не только на 1280. Source: user

- Свечение у повёрнутых на 45° элементов (ромбы) — только `filter: drop-shadow`, `box-shadow` даёт размытое пятно. Source: user
- У сайта многие блоки с `max-height`/фиксированной высотой и `overflow: hidden` (заголовки новостей, лента «Темы дня») — внутренние отступы съедаются, задавать снаружи или менять высоту.

- `tools/audit.js` видит только отрисованные элементы: выпадающие меню, спойлеры, `:hover` проверять принудительно.
- Предпросмотр проксирует файлы сайта через себя — иначе иконочный шрифт `shikimori` режется CORS и вместо иконок видны прямоугольники.
- Пользователь ждёт редизайна, а не перекраски: шапка, карточки, акценты должны заметно отличаться от стандартного Shikimori. Source: user

- Пользователь не хочет «прыжков» при наведении: никаких `translate`/`scale` у карточек, тегов, полос — только
  рамка и свечение; увеличивать можно картинку внутри обрезанной рамки. Source: user
- Сайт меняет поля у `.b-tag[href]:hover` и красит нижнюю рамку `.b-tag[href]` в синий; подчёркивания ссылок —
  ~250 правил `:hover { text-decoration: underline }` и нижние рамки через `--link-border-*` (в теме прозрачные).
- Иконки шапки у сайта — шрифт `shikimori` в `::before`; «Топ» — подпункт с абсолютной «веткой» `::before`;
  подменю скрыто `display: none` и открывается скриптом (на десктопе — наведением), сетку включать только на `.active`.
- Высота шапки — переменная сайта `--top-menu-height` (у сайта 46px): от неё считаются отступ страницы,
  выпадающие списки и поиск. В теме ≥768px — 60px. Шапка в потоке страницы (`position: relative`), не фиксирована.
  Пользователю не нравится тесная шапка: элементы 40px, отступы 8–18px, края — по краям контента. Source: user
- Не уменьшать звёзды оценки через `zoom`/`transform`: сайт считает оценку по координатам курсора — «10» не ставится.
- «Добавить в список»: высоту и анимацию списка задаёт скрипт (`style="height"`) — не перебивать `!important`,
  иначе не сворачивается. Список поверх: `position: absolute`; в «Связанном» снимать позиционирование с
  `.b-height_shortened` и `.b-user_rate` и маску затухания, пока `.expanded` (маска обрезает и выпавшее).
- У заголовков `.headline/.subheadline` сайта `overflow: hidden` — светящийся ромб ::before обрезался слева;
  запас даёт `padding-left` с таким же отрицательным `margin-left`.
- Не менять фон с градиента на цвет при `:hover` с `transition: background` — градиент не анимируется, полоса «моргает»;
  подсветка через `filter: brightness`.
- Кликабельность: у «таблеток»-ссылок поля и рамка — на самой `<a>`, а не на обёртке; заголовок, где ссылка
  единственная (`> a:only-child`), — ссылка во всю строку (стрелка — её ::before у правого края). Source: user
- Блок «Избранное» в профиле сайт собирает сам: 10 случайных записей из всего избранного, выборка держится
  какое-то время. Выбирать через CSS нельзя; в теме — свои ленты `.bj-fav` из «О себе» (все ID), блок сайта
  скрыт через `:has(.bj-fav)`. Разметку `[characters ids=…]` вживую ещё не видели — проверить после вставки.
  Число записей задаёт настройка «Количество избранного в профиле» (Настройки → Профиль, поле
  `favorites_in_profile`, по умолчанию 10); тема оставляет не больше 6 в группе (`:nth-child(n+7 of …)`).
- Редактор «О себе» у пользователя — старый (BB-код прямо в поле), переключателя «Код» нет. Source: live page
- Кнопка «наверх» — `.b-to-top` (только ≥1024px): полоса `.slide` во всю высоту слева и `.arrow` внизу.
- Любое `@media` в CSS снимает автообёртку `min-width: 1024px` со всего стиля.
- Санитайзер удаляет целые слова `this`, `parent`, `window`, `script` и др. — молча.
- Комментарии вырезаются из итогового CSS.
- `@import` внутри импортированного файла не работает (вырезается).
- На ≤1023px сайт принудительно убирает фон `body`.
- Кеш `@import` — 8 ч; сброс через `/tests/reset_styles_cache`. Но собранный CSS лежит в БД и обновляется
  только при сохранении поля: после `git push` нужен сброс кеша и пересохранение, иначе сайт показывает старую тему.
  Номера `?v=` в адресе импорта не использовать — пользователя это раздражает. Source: user
  Проверено 2026-09-25: после нескольких push живой `#custom_css` оставался первой версией (113 КБ).

## Notes

Source tags: `Source: user`, `Source: code`, `Source: docs`, `Source: inference`, `TODO:`.

- Если в «О себе» только `[div=bj-fav]`, заголовок «Обо мне» скрыт (`about.css`) — блок выглядит разделом «Избранное»; карандаш редактирования (только владельцу) остаётся справа, ссылке «Всё избранное» даётся `padding-right: 40px`.
- Ленты избранного бесконечные: в каждой `[div=bj-fav-row]` два одинаковых BB-тега (две копии списка), каждая копия едет на `translateX(-100%)` по кругу; `padding-right: 10px` копии = шаг стыка (проверено: стык 10px, как между карточками). Аниме — влево, персонажи — `animation-direction: reverse` (вправо). Со старым BB (одна копия) лента прыгает в начало.
- При `.bj-fav` в «О себе» `.profile-content` — flex-колонка, `.achievements { order: 1 }`: «Избранное» над «Достижениями».
- Лента избранного с одной копией (`:only-child`) едет туда-обратно (`bj-fav-sway`), иначе лента персонажей (reverse) начиналась бы с пустоты.
- График активности: числа в столбцах — часы за период (из title: «212 часов с … по …»), а не количество аниме. У низких столбцов (`.value.narrow`) сайт число не выводит — так и оставлено по решению пользователя (пробовали подсказку из title, отказались).
- Производительность профиля: не ставить `backdrop-filter`/`filter: blur` на элементы поверх анимаций (баннер, ленты избранного) — размытие пересчитывается каждый кадр, баннер дёргается. Убрано: у шапки (фон и так непрозрачный), у `.c-info` (фон `.86`), у `html::after` (свечение), у `.collection_score` в лентах (сайт ставит `backdrop-filter: blur(3px)`). Анимировать только `transform`/`opacity`: блик баннера — отдельный слой `body::after` с `translateX`, затемнение арта — в `body::before` поверх картинки (раньше `background-position` каждый кадр).
- Наезд камеры на арт баннера (`bj-kenburns`) убран по просьбе пользователя: медленный зум выглядел «покадровым». Арт статичный, остались блик и бегущий текст. Не возвращать медленный scale большого фона.
- Баннер профиля — во всю ширину экрана (пользователь против ограничения по ширине, откатано). Арт 16:9 при `cover` на 1868×480 показывает лишь ~46% высоты картинки — «уместить целиком» без смены высоты баннера или пустых полей нельзя; варианты предложены пользователю. Не менять раскладку баннера без его согласия.
- Бегущий текст: `content: var(--bj-ghost) ×3`, `translateX(-33.333%)` linear 60s infinite + `will-change` — бесконечная строка без замедлений (с ease-in-out alternate шла ступеньками). Во всю ширину экрана, как баннер (просьба пользователя): `left: calc(50% - 50vw)` от центрированного `.l-page`, обрезка справа — `overflow-x` у html/body.
- «Добавить в список»: в несвёрнутом «Связанном» список лежит в `.info { overflow: hidden }` — открывался невидимым («срабатывает не всегда»); при `.expanded` снимаем overflow. На странице тайтла `.c-image` — `position: sticky` (свой слой): блоки ниже перекрывали список; при `.expanded` `.c-image { z-index: 50 }`. Проверено `elementFromPoint` по списку в обоих местах.
